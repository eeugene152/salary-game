## Этап 1: Базовый прототип (MVP в одном компоненте)

На этом шаге реализована основная бизнес-логика приложения внутри единого компонента `App.tsx` без разбиения на модули и без передачи пропсов.

### Что реализовано и отработано:
1. **Конечный автомат (State Machine) на одном хуке `useState`:**
   - Вместо управления видимости элементов через CSS (`display: none`), интерфейс полностью зависит от текущего состояния: `UI = f(state)`.
   - Состояние строго типизировано через объединение литералов: `type TStep = 'start' | 'fired' | 'smile'`.
2. **Условный рендеринг через оператор `&&`:**
   - В зависимости от значения `step` React отрисовывает только один из трёх экранов:
     - `'start'` — стартовый экран с кнопкой запроса повышения.
     - `'fired'` — экран отказа («Вы уволены!») с двумя вариантами ответа.
     - `'smile'` — финальный экран со смайлом и кнопкой выхода.
3. **Обработка событий (`onClick`):**
   - Переходы между экранами реализованы через передачу стрелочных колбэков `onClick={() => setStep('...')}`, чтобы предотвратить мгновенный вызов сеттера при рендере страницы.

### Ограничения текущей версии (причина будущего рефакторинга):
- Весь код и разметка находятся в одном файле `App.tsx`.
- Экран `'fired'` сейчас реализован как обычный `div` в потоке документа, а не как полноценное модальное окно поверх страницы с затемнением фона и закрытием по клавише `Escape`.

## Этап 2: Вынесение компонента `Modal`, композиция и работа с браузерными событиями

На этом этапе блок уведомления об увольнении вынесен из `App.tsx` в независимый переиспользуемый компонент `src/components/Modal.tsx` со своими стилями (`Modal.css`).

### Что реализовано и отработано:

1. **Композиция компонентов (избавление от Props Drilling):**
   - Вместо прокидывания множества мелких данных и обработчиков вниз по цепочке, компонент `Modal` спроектирован как универсальная «коробка» с двумя слотами:
     - `children: ReactNode` — основной контент окна (передаётся между открывающим и закрывающим тегами `<Modal>...</Modal>`).
     - `footer: ReactNode` — блок с кнопками управления (передаётся как готовый JSX-фрагмент через пропс).
   - Сам компонент `Modal` остаётся «глупым» и ничего не знает о бизнес-логике зарплаты или шагах сценария.

2. **Закрытие окна по клавише `Escape` (хук `useEffect` + очистка):**
   - При монтировании модального окна запускается `useEffect`, который вешает глобальный слушатель `document.addEventListener('keydown', handleKeyDown)`.
   - При нажатии `Escape` вызывается переданный от родителя колбэк `onClose()`.
   - Обязательно реализована **функция очистки** (`return () => document.removeEventListener(...)`), которая удаляет слушатель при размонтировании окна, предотвращая утечки памяти и фоновые срабатывания.

3. **Закрытие по клику на оверлей и остановка всплытия (`stopPropagation`):**
   - На внешний тёмный фон (`.overlay`) повешен обработчик `onClick={onClose}`.
   - На внутреннюю карточку окна (`.modal-window`) добавлен стоп-кран `onClick={(e) => e.stopPropagation()}`, чтобы клики по тексту или пространству внутри самой карточки не «всплывали» к родителю и не закрывали окно.

4. **Изоляция стилей и Flexbox-раскладка:**
   - Создан отдельный файл `Modal.css` для позиционирования модального окна поверх экрана (`position: fixed; inset: 0`).
   - Для выравнивания кнопок в столбец с равномерными отступами применены свойства `display: flex; flex-direction: column; gap: 10px`.
